v1.1.0 Flagship

Meet fbk doctor: a self-evolving space playbook that learns your machine.

Every checkup and cleanup writes back into a personal <state_dir>/playbook.md—never dirtying your repository—so recommendations sharpen as your stack and habits evolve.

01 · HARDLINK AWARE

Samples st_nlink > 1 vs. true hogs

Distinguishes pnpm hardlinked node_modules (reminding you to run pnpm store prune) from exclusive physical disk eaters like Rust target/ and Next.js .next/cache.

02 · AUTO-CLEAR WINS

Fixed issues promote to Resolved Wins

Fix a flagged .gitignore trailing slash (node_modules/) and re-run doctor: the warning automatically promotes into Resolved Wins in your playbook.

03 · ACTION FEEDBACK

Real cleanup telemetry feeds back

Every slim, clean, or close --apply feeds actual reclaimed GBs and recurring hotspot repositories back into your profile.

04 · --learn & --no-evolve

Capture team gotchas anytime

Run fbk doctor --learn "..." --stack js-ts or tell your agent to remember a rule. Need a strict zero-write probe? Pass --no-evolve.

Zero-Guesswork Architecture

4-Tier Fail-Closed protection & hardened Recovery Vault.

Read-only probes always pass --no-optional-locks, virtual squash probes touch zero loose repo objects, and every non-ancestor delete snapshots a verifiable .bundle first.

TIER 0 · SAFE AUTO

Merged & clean

Ancestor, cherry-pick, or virtual squash-merged branches past the 24h grace period with zero active lsof processes.

TIER 1 · CACHE SLIM

Trim caches, keep code

Removes idle node_modules, .next, target, dist, .venv across 3 nested levels after verifying zero git ls-files.

TIER 2 · REVIEW + VAULT

Dirty or unmerged

Requires --allow-review / --allow-dirty and writes a .bundle + diff + untracked .tar.gz to Recovery Vault first.

TIER 3 · FAIL-CLOSED

Never auto-touched

Primary repos, protected branches, active lsof cwd, index.lock, .fbk-keep, .delivery, or 24h grace period.

FAQ

Frequently asked questions

Does fbk clean untracked node_modules and build caches if I keep the branch?
Yes. Run fbk slim --root . --apply (or ask your agent to slim idle caches). It recursively scans 3 levels for monorepos, checks lsof for active processes and git ls-files to protect tracked files, skips symlinks (follow_symlinks=False), and trims node_modules, .next, target, dist, and .venv without deleting your code or branch.
Why does deleting a pnpm worktree sometimes reclaim little disk space?
Standard pnpm hardlinks files in node_modules to a global store. Unlinking one worktree does not reclaim physical blocks while the store holds references. fbk doctor samples st_nlink > 1 to detect this and reminds you to pair cleanups with pnpm store prune (or enable virtualStoreType: global), while targeting exclusive physical hogs like target/ and .next/cache.
Does fbk doctor modify my Git repository or commit anything?
No. Your personal evolving playbook.md and evolution-profile.json live inside <state_dir> (~/.cache/fireworks-branch-killer or --state-dir), never inside your repo. Pass --no-evolve for zero state writes.
Can it safely detect GitHub Squash Merges and Rebase merges?
Yes. Unlike plain git branch --merged, fbk runs a zero-write 3-step waterfall: ancestor check → git cherry → virtual squash merge inside an isolated temporary GIT_OBJECT_DIRECTORY, writing zero loose objects into your real repo.
What happens if I regret deleting an unmerged branch?
Every non-ancestor deletion, detached unmerged HEAD, or dirty worktree snapshots a verifiable .bundle (plus git diff and untracked .tar.gz) into Recovery Vault before removal. Run fbk restore --list and fbk restore <receipt_id> --apply to recover cleanly.
Why does the skill work with Claude Code, Codex, and Amp without separate versions?
All three follow the open SKILL.md standard under .agents/skills/ (with .claude/skills/ symlinked or copied). Installing once via npx skills gives every compatible agent identical deterministic safety guardrails.
